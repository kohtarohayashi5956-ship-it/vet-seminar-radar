## 自動運用と障害時の確認

- 収集：GitHub Actions `Vet Seminar Radar`、毎週月曜・木曜06:00 JST（予定）。
- コード更新時にも巡回する。GitHub Actionsによる診断用コミットは新規巡回を要求しない。
- `data/collection_checks.json` の `published` と `publication_reason` を確認。`result=not_published, publication_reason=stale_source` は取得失敗と同義ではない。更新中にソースが変わったため、古い成果物の公開を防いだ状態。
- `data/release_checks.json` はオフライン検査の合否。`source_sha` が対象コード版と一致していることを確認。
- `data/run_status.json` の `checked_at_jst`・`warnings`・`source_results` を確認。公開完了は `collection_checks.json` だけでなく更新時刻と掲載内容でも照合。
- Actionsが失敗した場合、`Actions → Vet Seminar Radar → 該当run` で失敗したステップを確認。失敗の原因に対応する最小修正と回帰テストのみを実施。
- 掲載件数や料金記載率は品質監視指標であり、100%を合格条件にしない。
